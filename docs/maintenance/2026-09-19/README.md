# 2026-09-19：增量身份与恢复约束

本次维护发生在既有实验之后，不是新增模型或检索收益。

发现：`parent` 原先只是 manifest 注释，不参与版本身份；缺失父版本、删除/替换父记录均可发布，同一内容的独立快照还会覆盖请求的父血缘语义。
修复：父版本必须已登记且通过哈希检查；新快照保存全部原始记录的哈希多重集（含重复与隔离记录），要求父输入是子输入的子多重集。父版本进入版本身份，分片缓存仍由输入与算子内容决定。SQLite 连接显式关闭。

历史快照缺少原始记录哈希索引时拒绝作为增量父版本，需在新 lake 从原输入重建根快照。不会推断丢失的历史身份或改写旧资产。父输入验证为线性哈希/计数开销，未声明吞吐优化。

验证：`tests/test_incremental_contract.py` 覆盖不存在父版本、删除、替换、重复/隔离输入丢失、独立与子版本区分及幂等重放。`scripts/reproduce_portable.py` 用全部 2,403 条记录重建原有四类资产并比较字节，重新执行 dev 查询；新身份文件是额外产物。

`baseline/` 保存此次修改前、原冻结清单引用的源码字节（`.txt` 防止误导入）。核验器仍按原哈希检查这些历史源码；数据、配置、预测和报告仍检查原路径。当前算子哈希独立记录在新运行中，旧性能结果不归属于新实现。

真实 Ray worker 退出、driver 退出恢复与计时可以独立重跑：

```bash
PYTHONPATH=. .venv/bin/python scripts/systems.py --output work/systems-new
```

需要完整锁中的 Ray 和本机进程/端口权限。输出路径限定为新 `work/` 子目录，原有报告不覆盖。

另一项反例：相同 source_id 的相同记录被重复投递时，JSONL 血缘原先有两条边，而 SQLite 主键只保留一条。现在两种存储都保留唯一来源边；输入重复计数仍保留，不把重复投递算成两个来源。真实语料的既有资产字节不变。

本次本地验证：53 项测试通过；命令和修改后源码摘要见 [validation.json](validation.json)。这不是未推送提交的远端 CI 结果。

同机 2,403 条输入、新 lake、交错顺序各 3 次串行测量：[原始计时](evidence/serial-before-after.json)。中位耗时 0.296709 → 0.305233 秒（+2.87%），快照增加 168,333 字节；输出文档哈希一致。测量处于本机审查负载环境，次数少，不作显著性或加速结论。新增身份约束有存储/哈希成本。完整 [Ray 故障与计时记录](evidence/systems.json) 保留六项故障/恢复检查。
